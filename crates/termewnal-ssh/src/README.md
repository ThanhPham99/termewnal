# termewnal-ssh Source (`src`)

## Overview

`termewnal-ssh` implements the SSH client, host-key verification, authentication, proxy chaining, interactive PTY session supervision, port-forwarding tunnel management, SFTP browsing, and resilient SFTP file/directory transfer engine for Termewnal.

Built on `russh`, `russh-sftp`, `tokio`, `socket2`, `termewnal-core`, and `termewnal-pty`, the crate separates transport establishment (`client`, `auth`, `known_hosts`, `proxy_cmd`, `proxy_jump`, `proxy_net`, `x11`), supervised PTY lifecycle and telemetry (`session`, `supervisor`, `server_stats`), local/remote/dynamic port forwarding (`tunnel`), and pooled SFTP browsing plus resumable queued transfers (`sftp`, `transfer`, `dir_transfer`).

## Invariants

- **Strict Host-Key Verification & `known_hosts` Rules**:
  - `[client.rs:SshClientHandler::check_server_key]` rejects `KnownHostStatus::Mismatch` immediately with `Err(SshError::HostKeyMismatch)` without prompting the user; `KnownHostStatus::Unknown` prompts `SshInteractionHandler::verify_unknown_host` and accepts (`Ok(true)`) only on `HostKeyDecision::AcceptAndSave`, returning `Err(SshError::HostKeyRejected)` on `Reject`.
  - `[known_hosts.rs:verify_known_host_path]` treats a missing file as `KnownHostStatus::Unknown`, skips `@cert-authority` and unparseable lines, returns `Mismatch` immediately on any matching `@revoked` entry (overriding both prior and subsequent entries), records `first_mismatch` only when `entry.pubkey.algorithm() == pubkey.algorithm()`, matches `|1|...` HMAC-SHA1 hashed hosts and `*`/`?` patterns (vetoing lines containing matching `!` negated patterns), and matches `[normalized_host]:port` for `port != 22` or both unbracketed `normalized_host` and `[normalized_host]:22` for `port == 22` (`[known_hosts.rs:matches_host_patterns]`).
  - `[known_hosts.rs:record_known_host_path]` formats hosts via `[known_hosts.rs:canonical_host_token]` (`[host]:port` for non-default ports or IPv6), short-circuits without writing if `verify_known_host_path` already returns `Trusted`, and appends without an advisory file lock or atomic temp-file replacement.

- **Authentication & Secret Zeroization**:
  - `[auth.rs:RejectAllInteractionHandler]` unconditionally rejects unknown host keys and returns `None` for all passphrase, password, and keyboard-interactive prompts; `[sftp.rs:SilentTransferInteractionHandler]` uses the same non-interactive policy for background SFTP `Transfer` transports.
  - `[auth.rs:authenticate_with_public_key]` expands leading `~/` only (`[auth.rs:expand_tilde]`), tries explicit paths strictly or probes `<home>/.ssh/{id_ed25519,id_ecdsa,id_rsa}` in order via `[auth.rs:resolve_key_candidates]`, and aborts immediately on protocol/transport errors from `try_publickey_auth` while continuing across candidates on `load_private_key_with_vault` or rejected-key errors; `used_interactive` accumulates via `|=` across candidates.
  - `[auth.rs:load_private_key_with_vault]` skips unencrypted decode when `[auth.rs:requires_passphrase_upfront]` detects PEM or PuTTY encryption, checks `Vault` (`SecretStore::get_secret`) before prompting (never falling back to prompt if a stored passphrase fails to decode), and maps cancelled passphrase prompts to `SshError::KeyPassphraseRequired` (unlike password/keyboard-interactive cancellations, which yield `SshError::InteractiveCancelled`); `[auth.rs:authenticate_with_password]` falls back to prompting when `SecretStore::get_secret` returns `Ok(None)`.
  - `[auth.rs:try_publickey_auth]` queries `best_supported_rsa_hash()` for RSA keys (defaulting `None` to `Some(HashAlg::Sha256)`) and retries once with `hash = None` only when `!res.success()` and the advertised hash was `None`; `[auth.rs:authenticate_with_agent]` queries `best_supported_rsa_hash()` at most once without `None` fallback, attempts best-effort `bind_session` when `agent_session_binding()` is present, handles `AgentIdentity::Certificate`, ignores individual signing errors while trying remaining identities, and fails with `AuthenticationFailed` when `request_identities` is empty.
  - `[auth.rs:authenticate_with_keyboard_interactive]` replies with `Vec::new()` without invoking the UI handler when an `InfoRequest` has empty prompts, name, and instructions.
  - `[auth.rs:OsAgentConnector::connect]` supports Unix and Windows only, failing on other platforms with `SshError::Agent`.

- **Transport Precedence, Proxy Chaining, X11 & Forwarding Security**:
  - `[client.rs:SshConnectConfig::from_profile_with_sources]` rejects non-SSH `ProfileTarget`s, clamps `cols`/`rows >= 1`, and sets `nodelay = true`.
  - `[client.rs:SshTransport::connect_direct_with_options]` enforces transport precedence (`proxy_command` -> `proxy` -> direct TCP), fails before dialing if `proxy.vault_secret_ref` is `Some` while `vault` is `None`, bounds direct/proxy dialing to `DEFAULT_TCP_CONNECT_TIMEOUT` (15s), and forwards `keepalive` to both `apply_tcp_keepalive` (direct TCP) and `[proxy_net.rs:dial_via_proxy]` (proxy `TcpStream`) whenever `!ka.interval.is_zero()` (only `ProxyCommandStream` skips TCP keepalive).
  - `[client.rs:SshClientOptions::transfer]` uses an 8 MiB SSH window (`2 MiB` for `interactive`), clamps keepalive interval `>= 1s` and max missed `>= 1`, and enforces `silent_handshake_timeout` of 30s (`DEFAULT_TCP_CONNECT_TIMEOUT * 2`); `SshClientHandler::auth_banner` stores the banner in a private field; `connect_over_stream_with_options` sends best-effort `Disconnect::ByApplication` on auth failure; `exec_command` collects `ExtendedData` arriving before `ChannelMsg::Success` into `stdout`; `disconnect_shared` bounds `handle.disconnect` to 250 ms and `wait_closed` to 50 ms; `wait_closed` awaits only `self` (not `upstream_hops`).
  - `[proxy_cmd.rs:expand_proxy_command]` performs single-pass `%h`/`%p`/`%r`/`%%` substitution without shell quoting, and `[proxy_cmd.rs:ProxyCommandStream::spawn]` rejects empty expanded commands.
  - `[proxy_net.rs:dial_via_proxy]` trims `proxy.username` (treating empty user/password as `None`), bounds only the SOCKS5/HTTP handshake to `PROXY_HANDSHAKE_TIMEOUT` (15s), validates non-empty host and `proxy.port != 0`, enforces 255-byte SOCKS5 user/pass/domain limits, rejects `\r`/`\n`/`\0` in host/username/password before HTTP `CONNECT` (`[proxy_net.rs:contains_header_control_chars]`), reads HTTP headers 1 byte at a time up to `MAX_HTTP_HEADER_BYTES` (16 KiB) to avoid over-reading the SSH banner, applies `nodelay` + TCP keepalive, and wraps credential buffers in `Zeroizing`.
  - `[proxy_jump.rs:resolve_proxy_jump_hops]` ignores case-insensitive `"none"` segments, resolves hops in priority `saved_profiles` -> `openssh_hosts` -> literal (`port 22`, `Agent` auth, `$USER`/`$USERNAME`/`"root"` fallback), detects alias cycles (`visiting`), expands transitive jumps outermost-first without duplicating trailing prefixes, and skips alias lookup for bracketed or unbracketed multi-colon IPv6 literals; `[proxy_jump.rs:JumpHopSpec::to_connect_config]` clears nested forwarding/proxy/login-script fields on intermediate hops; `connect_chain_parts_with_options` dials targets via `direct-tcpip` over the last jump hop even when `proxy_command`/`proxy` is set; `[proxy_jump.rs:ChainBuildGuard]` and `[proxy_jump.rs:SshTransportChain::teardown_reverse]` tear down hops in strict inner-to-outer reverse order (`disconnect_shared` likewise disconnects `upstream_hops` in reverse).
  - `[client.rs:SshClientHandler::server_channel_open_agent_forward]` and `[client.rs:SshClientHandler::server_channel_open_x11]` reject server-initiated openings unless the corresponding forwarding flag and target (`agent_connector` / `x11_target`) were configured; `request_channel_forwarding` logs and ignores declined/failed agent/X11 requests (`single_connection = false` for X11); `[client.rs:RemoteForwardRegistry::find_sender]` matches `forwarded-tcpip` channels across 5 priority tiers.
  - `[x11.rs:parse_display_spec]` treats leading `/` as `UnixSocket`, `host:port` with `!host.is_empty() && num >= 6000` as raw TCP port override (`display_num = num - 6000`), and empty/`"unix"` host as `/tmp/.X11-unix/X{num}` if `sock.exists()` or `127.0.0.1:(6000_u16.saturating_add(num as u16))` otherwise (`connect_x11_target` returns `Unsupported` for `UnixSocket` on non-Unix); `[x11.rs:resolve_x11_auth]` prefers `display_override` over `$DISPLAY`, matches `$XAUTHORITY` / `~/.Xauthority` by `display_num`, falls back to the first valid non-empty `.Xauthority` entry, and otherwise generates a random 16-byte `MIT-MAGIC-COOKIE-1`.

- **Session Supervision, Keepalive Probes, Telemetry & Error Classification**:
  - `[error.rs:SshError::is_connection_error]` classifies transport/channel drops (`TransferTransportDropped`, `Disconnected`, `Connection`, `Channel`, `Russh`, `StatusCode::ConnectionLost`, transient `Io` error kinds, and drop-message `Sftp` errors) separately from auth, host-key, config, and remote permission errors; `[error.rs:map_remote_sftp_io_error]` prevents remote SFTP I/O drops from being misclassified as local `SshError::Io`.
  - `[session.rs:SshSession::open_on_buffer_with_options]` initializes session channel -> PTY (`cols/rows.max(1)`) -> forwarding -> shell in order before spawning `spawn_channel_pump`; `write_bytes` returns `Ok(())` on empty input even when disconnected and `ChannelWriteSink::write` discards send failures; unsupervised `Drop` disconnects automatically, while `from_supervised` snapshots `used_interactive_auth` once from the passed transport and delegates control to `ConnectionSupervisor` without disconnecting on drop.
  - `[supervisor.rs:SupervisorConfig]` `from_app_config`, `from_configs`, `ConnectionSupervisor::update_keepalive`, and `monitor_connected` clamp `keepalive_max_missed >= 1` (direct struct literal construction does not enforce it); `effective_probe_timeout` returns `probe_timeout.max(1 ms)` with no upper bound when `keepalive_interval.is_zero()`, and `probe_timeout.min(keepalive_interval).max(1 ms)` otherwise (returning `1 ms` when `0 < keepalive_interval < 1 ms`); `[supervisor.rs:compute_reconnect_backoff]` clamps `min >= 1 ms`, `max >= min`, exponent `<= 16`, jitter scale `[0.8, ~1.2]`, and final `jittered_ms` back into `[min, max]`.
  - `[supervisor.rs:SupervisorActor::attempt_connect_and_open_pty]` classifies `HostKeyMismatch` as `ConnectOutcome::FatalMitm` (causing `SupervisorActor::run` to emit `SupervisorEvent::MitmBlocked` and exit the actor loop permanently), `HostKeyRejected`/`InteractiveCancelled` as `FatalStop`, and `AuthenticationFailed`/`KeyPassphraseRequired`/`KeyLoad` as `FatalStop` only on initial connection (`!has_connected_once`), where `FatalStop` calls `park_disconnected` (`TransportStatus::Disconnected`, still resumable via `reconnect_now()`).
  - `[supervisor.rs:SupervisorActor::monitor_connected]` initiates an immediate probe on connect, treats `Ok` and `RequestDenied` on non-closed transports as alive (`[supervisor.rs:run_probe]`), runs `run_chain_probe` concurrently across all `ProxyJump` hops (using innermost `rtt_ms`, aborting on first `Dead` or `JoinError`) while watching `chain.wait_upstream_closed()`, resets `missed_probes` on inbound channel data (clamping `Degraded { missed_probes }` to `u8::MAX`), polls wake checks every `(keepalive_interval / 4).clamp(15ms, 1s)` (`1s` if zero) triggering fast wake probes on `wall_delta > threshold && wall_delta.saturating_sub(mono_delta) > threshold / 2` (fast probes overwrite in-flight periodic probes and `ProbeNow` wakes `Reconnecting`), emits `format_reconnected_divider` + `mux_attach_command` + `SupervisorEvent::Reconnected` only on reconnects (`has_connected_once`), runs `LoginScriptRunner` on both initial connect and reconnect, and marks `CleanShellExit` only when `exit_status.is_some() && !chain.any_hop_closed() && missed_probes == 0`.
  - `[server_stats.rs]` `POSIX_SERVER_STATS_COMMAND` probes `/proc/stat`, `/proc/uptime`, `/proc/meminfo`, `/proc/net/dev`, and `LC_ALL=C df -P -k / || df -k /` skipping `lo`/`veth*`; `parse_raw_server_stats` falls back to `MemFree + Buffers + Cached + SReclaimable` when `MemAvailable == 0`, re-filters `lo`/`veth*`, and errors if all four primary metrics are `None`; `ServerStatsCollector::update` prefers remote `uptime_secs` delta (`> 0.05s`), skips network updates if `dt_secs < 0.05` or counters regress, skips CPU updates unless `c_tot > p_tot`, and carries forward prior rates when no new delta can be computed.

- **Tunnels (`Local`, `Remote`, `Dynamic` SOCKS5)**:
  - `[tunnel.rs:validate_tunnel_rule]` refuses public binds without opt-in (`Err(SshError::TunnelPublicBindDenied)`); `[tunnel.rs:validate_target_host_port]` requires non-empty target host and non-zero port for `Local` and `Remote` tunnels; `[tunnel.rs:negotiate_socks5_connect]` enforces SOCKS5 (`0x05`) NO-AUTH (`0x00`) `CONNECT` (`0x01`) with valid address and non-zero port within `SOCKS5_HANDSHAKE_TIMEOUT` (`15s`); `DEFAULT_TUNNEL_HOLD_GRACE` is `10s`.
  - `[tunnel.rs:TunnelManagerInner::update_entry]` ignores updates whose `task_gen` does not match the current entry generation; `[tunnel.rs:TunnelManager::insert_managed_tunnel]` stops prior entries under the same ID before replacement; `start_standalone_tunnel` forces `rule.standalone = true` while `start_session_tunnel` does not normalize `rule.standalone = false` and returns a placeholder `SocketAddr` immediately for `Remote` tunnels; `[tunnel.rs:TunnelManager::stop_session_tunnels_internal]` stops and removes only non-standalone entries matching `session_id`, whereas `stop_tunnel`/`stop_all` retain entries as `Stopped` (preserving `Error` if `fatal_error.is_some()`); only `*_async` / `*_with_barrier` await done receivers (`CANCEL_TCPIP_FORWARD_TIMEOUT` `3s` + `1s`).
  - `[tunnel.rs:HeldGuard]` and `[tunnel.rs:ActiveConnGuard]` enforce RAII refcounts (`held_clients`, `active_connections`) across cancellation/drops; `[tunnel.rs:handle_local_client]` waits in `Holding` for a connected transport before negotiating SOCKS5 (enforcing a single cumulative `hold_deadline`, sending SOCKS5 `0x00` or `0x05` on `DirectOpenError::RemoteRejected`, without retrying remote `ChannelOpenFailure` rejections on open transports); `handle_remote_forwarded_stream` rejects with `AdministrativelyProhibited` if stopping or `ConnectFailed` on local dial error.
  - `[tunnel.rs:run_remote_tunnel]` registers local dispatch before requesting `tcpip_forward` (`[tunnel.rs:try_bind_remote_forward]`, settling up to `500 ms` on stop to cancel an in-flight bind), enters `TunnelState::Retrying` backoff (`1s..=30s`) on `RequestDenied` or `TransportError` while `!transport.is_closed()`, prevents re-attempting on a failed closed transport until a fresh transport connects, maps server-returned port `0` to `requested_port` when non-zero (`resolve_bound_remote_port`), and cancels non-closed remote forwards on exit; `reconnect_tunnel` wakes `Retrying` entries (rejecting non-`Retrying` session-bound tunnels with `TunnelConfig`).
  - `[tunnel.rs:StandaloneTransportDriver]` reads `time_source` never, calls `connector.connect` (not `connect_chain`), collapses `HostKeyMismatch`/`HostKeyRejected`/`InteractiveCancelled`/initial auth errors into `StandaloneConnectOutcome::Fatal` -> `TunnelState::Error` (no `MitmBlocked`), polls `is_closed()` every `STANDALONE_LIVENESS_POLL` (`50ms`) using `probe_timeout.max(1ms)` with no immediate connect probe and `latency_ms: None`, and `[tunnel.rs:StandaloneTransportDriver::shutdown_tunnel_then_transport]` stops the tunnel task (waiting up to `4s`) before closing the standalone transport.

- **SFTP Pool, Browser Safety & Resumable Transfers**:
  - `[sftp.rs:pipelined_sftp_client_config]` fixes SFTP pipelining at 256 KiB packets, 16 concurrent reads/writes, and a 30s timeout (`[sftp.rs:open_sftp_session]`).
  - `[sftp.rs:TransferTransportPool::acquire]` serializes per `ProfileTransportKey` via `key_mutex`, separates `Browser` and `Transfer` channel slots, immediately selects `SftpTransportMode::MuxFallback` on `primary_transport` when `used_interactive_auth()` is true (or on silent-auth-blocked errors when `active_primary` exists), and never falls back to a new transfer transport when a cached `MuxFallback` channel open fails.
  - `[sftp.rs:SftpManager]` retries browser ops up to `DEFAULT_SFTP_OP_MAX_RETRIES` (2) only on `is_connection_error()` with linear `retry_delay.saturating_mul(retry)` backoff (default `200 ms`, clamped `>= 1 ms`, woken by `pool.reconnect_notifier()`; `acquire_transfer_session` bypasses this loop); `[sftp.rs:SftpManager::read_text_file]` rejects oversized, NUL-containing, or non-UTF-8 files; `[sftp.rs:SftpManager::copy_file]` no-ops when `src_path == dst_path`; `[sftp.rs:SftpManager::remove_dir_recursive]` rejects `"/"`, `""`, and `"///"` and skips symlinks among `read_dir` children (without `lstat`ing the top-level `path`); `[sftp.rs:validate_remote_entry_name]` rejects empty, `.`, `..`, `/`, `\`, `\0`, or non-`Normal` path segments.
  - `[dir_transfer.rs:collect_local_dir_plan]` and `[dir_transfer.rs:collect_remote_dir_plan]` traverse BFS with real directories queued before symlinks and detect canonical symlink loops (`collect_remote_dir_plan` validates entry names via `validate_remote_entry_name`, whereas `collect_local_dir_plan` joins local names directly via `join_remote_path`), while `[dir_transfer.rs:UploadDirBatch::finish_file_and_finalize_dirs]` and `[dir_transfer.rs:DownloadDirBatch::finish_file_and_finalize_dirs]` apply masked (`& 0o7777`) directory permissions bottom-up only after all batch `TransferId`s finish (downgrading permission errors to `TransferNotice::PermissionPreserveSkipped`).
  - `[transfer.rs:TransferQueueConfig::sanitized]` clamps `max_concurrent_transfers >= 1`, `chunk_size` in `[128 KiB, 256 KiB]`, and `reconnect_retry_delay >= 1 ms`.
  - `[transfer.rs:TransferQueue]` guards worker-driven state mutations by `(id, generation)` (while queue-control ops `resolve_conflict`, `pause`, `resume`, `resume_reconnected`, `cancel`, `retry`, and `cancel_all` match by `id`/status predicates and bump `generation`), drops the `entries` mutex before calling `publish_snapshot`, retries transport-drop errors up to `max_transport_retries` with exponential backoff (`15s` cap + jitter, marking `failed_on_transport_drop = true` on exhaustion), deletes download `.part` files on `cancel` (handling `AwaitingConflict` too, unlike `cancel_all`), and caps auto-rename collision probing at `1..=1000`.
  - `[transfer.rs:ResilientTransferHook]` uses `.termewnal.part` staging strictly when `total_bytes > part_threshold_bytes` (never using `.part` when `total_bytes <= part_threshold_bytes`, even when `resume_existing_target` is true), attempts `posix_rename` unconditionally first in `finalize_upload` before falling back to `rename` with overwrite removal only when `overwrite_authorized` is true (mirrored locally in `rename_local_part_file`), while `[transfer.rs:TransferQueue::stream_upload]` performs upload source size/mtime invalidation and `is_part_fallback_status` (`PermissionDenied`/`OpUnsupported`/`Failure`) `.part` deletion + `force_direct_fallback` retry (uploads only).
  - **Lock poisoning**: Mutexes in `[supervisor.rs]`, `[tunnel.rs]`, `[sftp.rs:TransferTransportPool::key_mutex]`/`entries`, `[dir_transfer.rs]`, and `[transfer.rs:TransferQueue]` panic via `.expect(...)` if poisoned; `[client.rs:SshTransport::register_remote_forward]` panics on poisoned `remote_forwards` and `[session.rs:SshSession::transport_status]` panics on poisoned `status`, whereas `[client.rs:RemoteForwardRegistration]`/`auth_banner`/`server_channel_open_forwarded_tcpip`, `[session.rs:spawn_channel_pump]`, and `[sftp.rs:TransferTransportPool]` registration/invalidation/`status_notice`/`resolve_primary` helpers ignore poisoned locks.

## Side Effects

- **Network & SSH Protocol I/O**:
  - Outbound TCP connections (`TcpStream::connect`), SOCKS5 / HTTP `CONNECT` proxy negotiations (`[proxy_net.rs:dial_via_proxy]`), SSH handshakes (`client::connect_stream`), `direct-tcpip` jump-hop channels (`[proxy_jump.rs]`), PTY/shell/exec channels (`[client.rs:SshTransport]`, `[session.rs:SshSession]`, `[supervisor.rs]`), `keepalive@openssh.com` probes, and `tcpip-forward` / `cancel-tcpip-forward` global requests (`[tunnel.rs]`).
  - Socket tuning (`TCP_NODELAY`, `socket2` TCP keepalive in `[client.rs:apply_tcp_keepalive]` and `[proxy_net.rs:dial_via_proxy]`) and local TCP listener binding / `TcpStream::shutdown` (`[tunnel.rs:TunnelManager]`, `[tunnel.rs:reset_local_client]`).
  - Local X11 Unix socket / TCP dialing (`[x11.rs:connect_x11_target]`) and SSH agent Unix socket / Windows named-pipe / Pageant IPC (`[auth.rs:OsAgentConnector::connect]`).
- **Filesystem & Process Execution**:
  - Reads private key files (`[auth.rs:load_private_key_with_vault]`), `.Xauthority` (`[x11.rs:parse_xauthority_file]`), `known_hosts` (`[known_hosts.rs:verify_known_host_path]`), and local upload files/directories (`[transfer.rs]`, `[dir_transfer.rs]`).
  - Creates/updates `known_hosts` with `0o700` dirs / `0o600` file on Unix and `sync_all()` (`[known_hosts.rs:record_known_host_path]`), creates parent directories (`tokio::fs::create_dir_all`), sets download lengths (`set_len` on resume), writes/truncates/seeks/flushes/syncs/renames/deletes local download targets and `.termewnal.part` files, and sets POSIX permissions (`[transfer.rs]`, `[dir_transfer.rs]`).
  - Spawns local shell child processes (`/bin/sh -c` or `cmd /S /C`) via `[proxy_cmd.rs:ProxyCommandStream::spawn]` and terminates them on drop (`start_kill()` + `kill_on_drop(true)`).
  - Performs remote SFTP filesystem mutations (`create_dir`, `remove_file`, `remove_dir`, `rename`, `posix_rename`, `set_metadata`, file creates/writes/truncates) via `[sftp.rs:SftpManager]`, `[dir_transfer.rs]`, and `[transfer.rs]`.
- **Secrets, Environment, Concurrency & Shared State**:
  - Reads `Vault` secrets (`SecretStore::get_secret`) and prompts UI handlers (`SshInteractionHandler`) for passphrases, passwords, keyboard-interactive answers, and TOFU decisions; reads env vars `HOME`, `USER`, `USERNAME`, `DISPLAY`, `XAUTHORITY`, `SSH_AUTH_SOCK`.
  - Samples CSPRNG (`rand::rng()`) for X11 fallback cookies and reconnect backoff jitter; queries OS monotonic/wall clocks and local timezone (`Instant`, `SystemTime`, `chrono::Local` in `format_reconnected_divider`).
  - Spawns detached and tracked Tokio tasks/JoinSets for agent/X11/tunnel forwarding, upstream jump monitoring, channel pumps, supervisor actors, `ChainDropGuard::drop` reverse teardown, probe checks, delayed login scripts, zero-file directory upload creation/permission tasks (outside `semaphore`), and semaphore-bounded transfer workers; mutates `TerminalBuffer`, `Mutex`/`AsyncMutex` registries, atomic ID/flag counters, and `watch`/`broadcast`/`mpsc`/`oneshot`/`Notify` channels; emits `tracing::debug!` and `tracing::warn!` diagnostics.
